# LuaSandbox VM

**Компилятор и байткод-интерпретатор Lua 5.1 на чистом Lua для хостов, где недоступен `loadstring`.**

[English](README.md) | [Русский](README.ru.md)

![Lua](https://img.shields.io/badge/Lua-5.1%20%7C%20LuaJIT-2C2D72)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)

`custom_loadstring_full.lua` превращает строку с исходником Lua 5.1 в вызываемую функцию. Это один файл без зависимостей; он не использует `load`, `loadstring`, FFI, `debug`, `io` или `os`.

Подходит для игровых модов, встроенных рантаймов и небольших серверных песочниц, где нужно исполнять Lua-исходники без доступа к загрузчику хоста.

> **Для использования нужен только один файл:** `custom_loadstring_full.lua`. Папка `tests/` нужна для разработки, её можно игнорировать.

## Быстрый старт

Скопируй `custom_loadstring_full.lua` в проект и загрузи его:

```lua
local custom_loadstring = dofile("custom_loadstring_full.lua")

local env = {
    math = math,
    string = string,
    table = table,
}

local chunk, err = custom_loadstring([[
    local t = {}
    for i = 1, 5 do
        t[i] = i * i
    end
    return table.concat(t, ",")
]], env)

if not chunk then
    error("ошибка компиляции: " .. tostring(err))
end

print(chunk()) --> 1,4,9,16,25
```

Окружение задаётся явно. Если его не передать, чанк получит новую пустую таблицу, **а не** `_G`. Добавляй только те глобальные имена, которые разрешены скрипту.

## API

```lua
local chunk, err = custom_loadstring(source, env, options)
```

| Аргумент | Тип | Значение |
|---|---|---|
| `source` | string | Исходник Lua 5.1 |
| `env` | table или `nil` | Глобальное окружение; `nil` — новая пустая таблица |
| `options` | table или `nil` | Необязательные лимиты компиляции и выполнения |

Возвращает:

- вызываемую функцию Lua при успехе;
- `nil, error_string` при неверном аргументе или синтаксической ошибке.

Синтаксические ошибки содержат строку и ближайший токен. Ошибки выполнения выходят из чанка, поэтому лови их через `pcall`:

```lua
local ok, result = pcall(chunk)
if not ok then
    print("ошибка выполнения:", result)
end
```

### Опции и лимиты

Третий аргумент необязателен и обратно совместим. Он принимает положительные числа:

| Опция | По умолчанию | Значение |
|---|---:|---|
| `maxSourceBytes` | 4 МиБ | Максимальный размер исходника в байтах |
| `maxCodeSlots` | 8 000 000 | Максимум слотов байткода на прототип |
| `maxInstructions` | 50 000 000 | Инструкций VM на один вызов чанка |
| `maxCallDepth` | 10 000 | Максимальная глубина интерпретируемых вызовов |
| `maxStack` | 1 000 000 | Максимальный индекс стека значений VM |
| `maxArgs` | 1 000 | Максимум аргументов на вызов |
| `maxReturns` | 1 000 | Максимум возвращаемых значений |

```lua
local chunk, err = custom_loadstring(source, env, {
    maxInstructions = 5e6,
    maxCallDepth = 500,
    maxSourceBytes = 512 * 1024,
})
```

Лимиты включены по умолчанию. Чтобы отключить отдельный лимит, передай `math.huge`. Неизвестные поля игнорируются. Ноль, отрицательные числа и NaN приводят к ошибке компиляции.

Возвращённый чанк можно вызывать много раз. Локальные переменные создаются заново при каждом вызове; таблица окружения общая.

## Поддержка языка

Компилятор рассчитан на Lua 5.1:

- `if`, `while`, `repeat`, числовой и generic `for`;
- функции, замыкания, upvalue, varargs;
- таблицы, методы, множественное присваивание и возврат;
- все операторы Lua 5.1;
- метатаблицы через хост;
- `getfenv`/`setfenv`, если они есть в хосте.

Синтаксис Lua 5.2+ вроде `goto`, `//`, `_ENV` и атрибутов переменных не поддерживается. В Lua 5.1 нет побитовых операторов; если они нужны, передай через `env` библиотеку вроде `bit`.

## Безопасность

Это интерпретатор с ориентацией на песочницу, **но не защищённая граница безопасности**.

- Лимиты инструкций, глубины вызовов, стека, аргументов и возвратов включены по умолчанию и настраиваются через `options`.
- Нет таймаута по времени; для враждебного кода используй отдельный процесс/воркер с внешним таймаутом.
- Нет лимита памяти внутри Lua.
- Глубина рекурсии ограничена `maxCallDepth`, но tail-call optimization всё ещё отсутствует.
- Любая функция хоста в `env` может делать всё, что умеет эта функция.
- Не передавай `os`, `io`, `debug`, `package`, `loadstring` или FFI недоверенному коду.
- `getfenv`/`setfenv` специально обрабатываются только для интерпретируемых замыканий. Доступ к окружению native-функций запрещён.

Для недоверенных скриптов дополнительно используй отдельный процесс/воркер, таймауты и лимиты памяти вне Lua.

## Тесты

Из корня репозитория:

```bash
luajit run_all_tests.lua
```

или:

```bash
lua run_all_tests.lua
```

Ожидаемый результат:

- LuaJIT: **18 658 проверок**, 0 ошибок;
- Lua 5.4: **18 640 проверок**, 0 ошибок (часть проверок `setfenv`/`getfenv`/`__len` пропускается).

Папка `tests/` нужна только для разработки; для использования библиотеки её можно не читать. Подробное покрытие — в [`tests/README.md`](tests/README.md).

## Производительность

На микробенчмарках проекта интерпретатор оказался примерно **в 1.6 раза быстрее FiOne** в среднем после peephole/super-инструкций. Он всё равно значительно медленнее нативного LuaJIT — это другая модель исполнения. Это микробенчмарки, а не репрезентативная нагрузка игры.
